## 原因と変更

身支度は、羊皮紙上の見出し・装備の定義リスト・手荷物カードが縦に続く画面だった。意識と共通の布地パネルにし、人物と選択品の説明を上段、装備3枠と手荷物2枠を下段に配置。縦画面は下、横画面は右に寄せ、共通のカメラ余白計測を使う。身支度中の移動入力停止、武具棚の年齢・距離制限、手荷物の実コマンドは保持。

技の配分コマンドと武器変更には採用数の上限がなかった。共通定数 `MAX_PHASE_SKILLS=5` を設け、各段の6つ目の追加を画面と Simulation の両方で拒否する。5つの葉形の印が使用枠を示す。満杯時も既存技を外せ、配分変更も可能。武器変更は基本技を習得するが、5枠が埋まっていれば既存採用を押し出さない。

旧データの超過配分は、値が大きい順、同値はID順で5つを残す。残りは配分0とし、技自体を保持。変更前の全段配分を `phaseWeightsBeforeLimit` に保管する。再読み込みでは再度上限を確認し、元のバックアップは上書きしない。セーブの schema 3 と技IDは維持する。

既存の faith 演算子には「小さな信仰」4061があるが、新しい経験カタログに信仰を示す習得先がなかった。60904 `bl.skill.deep_faith`「篤い信仰」を追加。教会での祈りを条件とし、既存の経験・閃き・来歴・保存処理を通す。faith 強度2で既存の信仰条件を満たし、奇跡の発動率を6ポイント上げる。小さな信仰だけの発動率は維持。両方ある場合は12ポイント増、最終確率は90%を上限とし、確定発動にはしない。新しい通貨・信仰ゲージは作らない。
